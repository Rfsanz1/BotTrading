## Constraints

No Binance credentials were used and no live order was submitted. Runtime collectors use public market-data endpoints only. Missing data now raises an explicit error rather than being converted into a numeric zero or empty structure.

## Runtime interval normalization update — 2026-09-23

The active runtime defect was that scheduler/internal timeframe values such as `1H` were passed unchanged to Binance Spot `/api/v3/klines`, which requires `1h`. The fix adds the explicit `toBinanceSpotInterval()` mapping at the shared Binance client boundary, keeps internal/canonical names intact, applies the same mapping to Futures klines and kline WebSocket subscriptions, and rejects invalid timeframes before a request is made. Symbol normalization now removes all separators, so `BTC/USDT` and `ETH/USDT` reach Binance as `BTCUSDT` and `ETHUSDT`.

Non-2xx Binance responses now preserve safe diagnostic fields in the propagated error (`status`, `endpoint`, `symbol`, `interval`, `binanceCode`, and `binanceMessage`) without logging credentials. The Docker health check and operational test script use the actual Nest `PORT` (3001 in the active compose configuration), not the obsolete 3000 value. The rebuilt container became healthy on port 3001; post-restart scheduler logs showed no invalid-interval 400 responses. The scanner completed without interval errors; its zero-candidate result was due to an empty enabled symbol registry in this runtime.

## Symbol universe correction — 2026-09-23

The zero-candidate root cause was the empty in-memory `SymbolRegistryService`: there was no production hydration path. The registry now uses the existing Binance client to fetch public Spot `exchangeInfo`, normalizes symbols, filters `TRADING` USDT Spot symbols with Spot permission and parseable filters, deduplicates them, and atomically replaces only the Spot registry. Startup hydration runs before scheduled work; refreshes repeat using `BINANCE_SYMBOL_REFRESH_MS` (five-minute default) with overlap protection.

Failed discovery preserves the last-known-good registry and marks health `DEGRADED`; an initial failure is `INVALID` and prevents scanning. Scheduler logs now include registry status, symbols seen, eligible/rejected counts, and candidate count. No production BTC/ETH/SOL list was added.
